# ทดลองบทแรกกับผู้เริ่มเรียน

สถานะ: **คู่มือเตรียมทดสอบ ยังไม่มีผลจากผู้เล่นจริง** ไม่ใช้ผล browser automation แทนผลจากคน

เป้าหมาย: ผู้เริ่มเรียนอย่างน้อย 5 คน อายุประมาณ 12 ปีขึ้นไป อย่างน้อย 4 คนเริ่มรันโค้ดและอธิบายคำตอบแรกได้โดยผู้ดูแลไม่เฉลย ใช้เวลาประมาณ 15 นาทีต่อคน

## เตรียม

- เปิดเกมในโปรไฟล์ทดสอบหรือหน้าต่างส่วนตัวใหม่ แยกจากเซฟที่ผู้ใช้เล่นจริง ไม่รีเซ็ตความคืบหน้าของผู้อื่น
- ให้ผู้เล่นเลือกคอมพิวเตอร์หรือโทรศัพท์ที่คุ้นเคย เก็บขนาดหน้าจอ ระบบปฏิบัติการ และเบราว์เซอร์ไว้กับผล
- ใช้รหัส P1–P5 แทนชื่อ ไม่ต้องสมัครบัญชีหรือให้ข้อมูลส่วนตัว
- เริ่มจับเวลาที่เห็นหน้าเลือกอาชีพ บันทึกสิ่งที่ผู้เล่นทำและคำพูดสั้น ๆ ไม่อธิบายคำตอบล่วงหน้า

## คำชวนและงาน

1. “ลองเริ่มการผจญภัยและเข้าห้องแรกตามที่เข้าใจได้เลย” สังเกตการเลือกอาชีพและการหาห้อง
2. “ลองเขียนข้อความที่ชอบ แล้วพาตัวละครต่อสู้” ให้ใช้ภารกิจ โค้ดตั้งต้น และคำใบ้ในเกมตามต้องการ
3. ก่อนรัน ถาม “คิดว่าแต่ละบรรทัดจะทำอะไร” แล้วให้ผู้เล่นกดรันเอง บันทึกเวลาถึงการรันครั้งแรกและความเข้าใจเรื่อง `print()` กับคำสั่งต่อสู้
4. “ลองเปลี่ยนแผน แล้วดูว่าจะเกิดอะไรขึ้นก่อนส่งเทิร์นจริง” สังเกตว่าพบปุ่มตรวจแผนหรือไม่ แยกผลคาดการณ์ออกจากผลที่ส่งจริงได้หรือไม่
5. “ลองเขียน `attack(1)` หนึ่งครั้ง แล้วใช้ข้อความของเกมช่วยแก้” สังเกตว่ารู้ว่าต้องแก้บรรทัดไหนและไปบรรทัดนั้นได้หรือไม่ งานนี้เป็นข้อผิดพลาดที่จัดไว้ จึงไม่นับเป็นความผิดพลาดที่เกิดเอง
6. ให้เดินต่อเท่าที่เวลาเหลือ ก่อนส่งหนึ่งเทิร์นถาม “ศัตรูกำลังจะทำอะไร และทำไมเลือกคำสั่งนี้” สังเกตการอ่านท่าศัตรูและต้นทุน AP/MP
7. กลับแผนที่แล้วเปิดห้องเดิม ตรวจว่าผู้เล่นเข้าใจการเล่นต่อและยังหาโค้ดเดิมเจอ

ถ้าผู้เล่นติด ให้ถามว่า “ตอนนี้กำลังมองหาอะไร” หรือชวนอ่านสิ่งที่อยู่บนจอ บันทึกว่าได้รับความช่วยเหลือ หากต้องบอกคำสั่งหรือคำตอบโดยตรง ให้นับงานนั้นว่าต้องช่วย

## เกณฑ์บันทึก

บันทึกข้อสังเกตเพิ่มเติมโดยไม่เปลี่ยนเกณฑ์ 4/5 ด้านบน:

- หากผู้เล่นเปิดคำใบ้ระดับสามเอง ให้บันทึกว่าคาดผลพิมพ์ก่อนเปิดดูหรือไม่ และอธิบายได้หรือไม่ว่าจะนำแนวคิดจากตัวอย่างไปใช้กับโค้ดของตนอย่างไร ผู้ดูแลไม่กดเปิดผลหรือบอกคำสั่งต่อสู้แทน
- หลังชนะครั้งแรก ให้ผู้เล่นเดินต่อเอง สังเกตว่ารู้ว่าการต่อสู้จบแล้วและพบทางไปห้องถัดไปหรือไม่ โดยยังไม่ชี้ปุ่มให้ หากแพ้ระหว่างเล่น ให้บันทึกว่าพบการลองใหม่และทราบว่าโค้ดเดิมยังอยู่หรือไม่
- เก็บคำอธิบายและสิ่งที่เห็นจริงแยกจากความเห็นของผู้ดูแล การผ่านแคมเปญด้วยโค้ดอ้างอิงในระบบอัตโนมัติไม่ใช่หลักฐานว่าผู้เล่นเข้าใจแนวคิด

## โทรศัพท์จริง

ตรวจอย่างน้อย Android Chrome และ iPhone Safari โดยเปิดคีย์บอร์ดจริง:

- พิมพ์และแก้โค้ดหลายบรรทัด ตัวอักษรไม่เล็กลงอัตโนมัติ และไม่มีการเปลี่ยนคำหรือเครื่องหมายคำพูดจาก autocorrect
- ใช้ปุ่มย่อหน้า วงเล็บ คำพูด และสกิล แทรกคำสั่งแล้วแก้ต่อได้
- กดตรวจแผนและรันครั้งเดียวแล้วทำงาน ปุ่มไม่ขยับหนี และไม่ถูกคีย์บอร์ดบัง
- ทำให้ชนะและแพ้อย่างละหนึ่งครั้ง ตรวจว่าหลังแอนิเมชันจบเห็นหัวข้อและปุ่มไปต่อหรือลองใหม่ คีย์บอร์ดไม่เปิดกลับเอง และโค้ดเดิมยังอยู่หลังลองใหม่
- เปิดตั้งค่าขณะแอนิเมชันเทิร์นสุดท้ายยังเล่นอยู่ ตรวจว่าผลการต่อสู้ไม่แย่งโฟกัสหรือเลื่อนหน้าต่าง และปิดตั้งค่าแล้วไม่มีการเลื่อนไปหาผลเดิมซ้ำ
- เปิด/ปิดสมุดสกิล หมุนจอ และกลับจากหน้าต่างอื่น โค้ดไม่หายและหน้าไม่เลื่อนขวาเกินจอ
- เปิดห้องเดิมหลังปิด/เปิดหน้าใหม่ แล้วตรวจ HP/MP เทิร์น และ draft

เก็บภาพจอของฉากและ editor ขณะคีย์บอร์ดเปิด พร้อมรุ่นอุปกรณ์และเบราว์เซอร์ เมื่อมีหลักฐานแล้วจึงอัปเดต VERIFICATION.md ว่าผ่านอุปกรณ์ใดจริง

## หลังทดลอง

สำหรับรุ่นที่ปรับตัวตรวจบทเรียนและโจทย์บอส ให้สังเกตเพิ่มโดยไม่เปลี่ยนเกณฑ์เริ่มเล่น 4/5 คนด้านบน:

- เมื่อพบภารกิจ `if` ให้ผู้เล่นชี้ว่าคำสั่งใดอยู่ใต้เงื่อนไข และคาดว่าจะเกิดอะไรเมื่อเงื่อนไขเปลี่ยน ให้ลองเองโดยไม่เฉลยโค้ด
- เมื่อถึงบอส ให้ผู้เล่นอธิบายว่าใช้ความรู้เรื่องใดร่วมกัน และลองเปลี่ยนข้อมูลหนึ่งค่าเพื่อดูว่าแผนยังทำงานหรือไม่ เก็บเวลาที่ใช้และระดับคำใบ้ แยกผลแต่ละบท ไม่ถือว่าการชนะเท่ากับอธิบายได้
- จับเวลาถึง Python พร้อมและการรันแรกแยกกัน บันทึกว่าเป็นการเปิดครั้งแรกหรือเคยเล่นออฟไลน์แล้ว พร้อมชนิดเครือข่าย ไม่เปรียบเทียบข้ามอุปกรณ์โดยไม่ระบุเงื่อนไข
- ในโปรไฟล์ทดสอบที่มีอัปเดตรออยู่ ให้ลองเข้าห้องและแก้โค้ดต่อ จากนั้นรอ “บันทึกแล้ว” ปิดแท็บเกมทั้งหมดและเปิดใหม่ ตรวจว่าห้องและร่างเดิมยังอยู่ ห้ามนำเซฟจริงของผู้อื่นมาใช้กับงานนี้

แยกสิ่งที่เห็นออกจากข้อสันนิษฐาน จัดลำดับปัญหาที่ทำให้เริ่มเล่นไม่ได้ โค้ด/เซฟหาย หรือเข้าใจบทเรียนผิดก่อนความสวยงาม หากไม่ถึงเป้าหมาย 4/5 ให้แก้จุดที่พบและทดลองซ้ำกับผู้เริ่มเรียนใหม่ ไม่แก้ผลในตารางให้ดูผ่าน
