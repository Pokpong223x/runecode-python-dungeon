# เลือกโจมตีปกติหรือสกิล

เพิ่มเติมภายหลัง: [สกิลหลายท่าและ AP ตามบรรทัด](SKILLS-AND-AP.md) เพิ่ม `pierce()`, `stun()` และ `burst()` ตามอาชีพ โดยคงกติกาหนึ่งท่าโจมตีต่อเทิร์น ท่าเดิม `skill()` ยังเหมือนเดิม

ที่มา: คำขอผู้ใช้หลังจบรอบพัฒนา 8 ชั่วโมง ให้เลือกโจมตีปกติหรือสกิล และเปลี่ยนโค้ดตามที่เลือก ตีความเป็นการเลือกต่อเทิร์นตามคำอธิบายในแชต การเลือกนี้แทนกฎเดิมที่อนุญาต attack + skill รวม 3 AP

- แต่ละเทิร์นใช้ `attack()` หรือ `skill()` อย่างใดอย่างหนึ่ง เปลี่ยนท่าได้ก่อนรันทุกเทิร์น
- `attack()` ใช้ 1 AP; `skill()` ใช้ 2 AP และ 4 MP ป้องกันหรือยาร่วมได้ภายใน 3 AP
- ปุ่มเลือกท่าเปลี่ยนชื่อคำสั่ง Python เดิมทันที หรือเพิ่มคำสั่งเมื่อยังไม่มี ไม่รันโค้ดหรือใช้ทรัพยากรทันที
- ถ้าโค้ดมีลูป/เรียกฟังก์ชันซ้ำ ผู้เล่นยังต้องปรับจำนวนครั้งให้ไม่เกิน AP เกมคงโครงบทเรียนไว้และอธิบายข้อจำกัดของสกิล
- ไม่แก้ข้อความ คอมเมนต์ เมธอดของ object หรือชื่อที่ผู้เรียนประกาศเอง โค้ดยังไม่สมบูรณ์จะเก็บไว้ให้แก้เอง พร้อมแจ้งเหตุผล
- การเปลี่ยนท่าย้อนกลับได้ในหนึ่ง Undo บันทึกเป็น draft ปกติ ไม่เปลี่ยนโครงเซฟหรือความคืบหน้า
- ตรวจรายการคำสั่งที่ Python เรียกจริงก่อนยืนยันเทิร์น จึงป้องกันการใช้ชื่อแทนเพื่อปนสองท่า แต่ยังเขียน if/else ที่เลือกเพียงท่าเดียวตอนรันได้
- ตัวอย่างอ้างอิงทั้ง 24 ห้องปรับให้ตรงกฎใหม่ และตรวจทั้งแนวคิด Python กับกติกาต่อสู้

เจ้าของ: `src/engine.ts` ตรวจคำสั่งจริง, `src/ui/offenseCode.ts` อ่าน Python syntax, `Editor` แก้ draft/Undo, `SkillBook` ใช้ร่วมทั้งในโซนขวาและ dialog, `App` ยืนยันเทิร์นและบันทึก

ผลตรวจรอบนี้: ดูส่วน Offensive choice ใน `VERIFICATION.md` และ `.verification/offense-regression.json` รุ่น ZIP ที่ส่งมอบในรอบ 8 ชั่วโมงเป็นหลักฐานรุ่นก่อนเพิ่มระบบนี้
