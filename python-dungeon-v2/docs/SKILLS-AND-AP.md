# สกิลหลายท่าและ AP ตามบรรทัด

ที่มา: ผู้ใช้ตอบ “ทำ” หลังข้อเสนอให้ทำ AP รายบรรทัดก่อน แล้วเพิ่มหลายสกิลต่ออาชีพ งานนี้เพิ่มสองระบบดังกล่าว โดยคงกติกาเลือกตีปกติหรือสกิลอย่างใดอย่างหนึ่งต่อเทิร์น

## กติกาและคำสั่ง

อัปเดต 26 ตุลาคม 2026: คำสั่งโจมตีและสกิลรับค่าพลังจำนวนเต็ม 1–3 ได้ เช่น `attack(2)`, `skill(3)`, `pierce(power)` ไม่ใส่ค่าเท่ากับพลัง 1 ระดับ 2/3 เพิ่มดาเมจตั้งต้น 4/8 ก่อนคูณผลสกิล โดยไม่เพิ่ม AP หรือ MP ดู [โจทย์ต้นฉบับ](SOURCE-CURRICULUM.md) ซึ่งต้องใส่ค่าพลังและออกท่าโจมตีหนึ่งครั้ง คำสั่งเสริมยังไม่รับค่าในวงเล็บ ตารางต่อไปแสดงอัตราคูณของสกิลตามเดิม

ทุกสกิลใช้ 2 AP จึงใช้ได้หนึ่งครั้งต่อเทิร์น และเหลือ 1 AP สำหรับป้องกันหรือยา ท่าทั้งสามเปิดให้เลือกทันที ไม่ต้องซื้อหรือรีเซ็ตเซฟ `skill()` เป็นท่าเดิมเสมอ

`src/skills.ts` เป็นเจ้าของชื่อ MP และผลของสกิล `engine.ts` ตรวจอาชีพ AP MP และคำสั่งผสมก่อน commit ทุกครั้ง การเปลี่ยนปุ่มเลือกท่าแก้ชื่อคำสั่งจริงรวมชื่อแทน โดยไม่แตะข้อความ คอมเมนต์ เมธอดของ object หรือจำนวนรอบในบทเรียน Undo/โหลดใหม่คืนการเลือกจาก draft เดิม

## AP จากการรันจริง

Python ส่ง trace ของคำสั่งที่ถูกเรียกจริง ไม่คำนวณจากจำนวนบรรทัดใน source จึงแยก branch ที่ไม่ทำงานและนับลูป/ฟังก์ชัน/ชื่อแทนได้ บอกทั้งบรรทัดเรียกคำสั่งกับลูปใน call stack

เก็บ trace สูงสุด 4 คำสั่งรวมคำสั่งที่ถูกปฏิเสธครั้งที่สี่ หากโค้ดจับ ValueError แล้วเรียกเกิน ก็ยังปฏิเสธทั้งเทิร์น หลังถึงขอบเขต แสดงค่า AP เป็น “อย่างน้อย” แทนการอ้างว่ารันลูปครบแล้ว

PythonFeedback เป็นจุดแสดงผลเดิม: AP แยกรายบรรทัดมีจำนวนครั้ง ค่า AP และปุ่มดูโค้ด หากเกินจะเปิดรายละเอียด ชี้บรรทัดแรกที่ทำให้เกิน และเสนอจำนวนครั้งตาม AP ที่เหลือ พร้อมปุ่มไปลูป โค้ดไม่ถูกแก้เองจากคำแนะนำ AP การแก้ draft ล้าง trace/ผลตรวจเก่า การรันผิด/ตรวจแผน/หยุดยังไม่เสียเทิร์นหรือทรัพยากร

ความเข้ากันได้: ไม่เปลี่ยน SaveGameV1 หรือทับเซฟเดิม `attack()`, `defend()`, `skill()`, `heal()` เดิมยังใช้ได้ ค่าและผลของท่าประจำอาชีพเดิมไม่เปลี่ยน

ผลตรวจและภาพหลักฐานรอบนี้อยู่ใน VERIFICATION.md และ `.verification/` การตรวจขนาดหน้าจอด้วยเบราว์เซอร์ไม่ใช่หลักฐานทดลองกับโทรศัพท์หรือผู้เรียนจริง
